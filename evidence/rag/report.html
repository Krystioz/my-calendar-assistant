Data and architecture

6 fictional documents, 19 heading-delimited chunks, 384-dimensional vectors. FastEmbed: sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2, cache .cache/fastembed/. The data/index.json index matches the documents in this checkpoint. Document search uses cosine similarity and top-3; separate calendar tools check availability. Answer model: google/gemma-4-26b-a4b-it, temperature 0; provider and outputs may vary.

LangGraph state stores messages, pending tool calls, retrieved source IDs, turn count and status. Transitions depend on the model's response to tool observations, rather than a fixed retrieve → answer pipeline. State persists within a run. At this checkpoint, clarify ended the CLI with a question; automatic conversation resumption and a persistent checkpointer were not implemented or explicitly required by the checkpoint.

Failure analysis

1. Fixed classification bug: “I do not know” reported as success

Before: for “Can I go to siupa lupa?”, the model returned plain text saying information was missing; the code assigned success without finish, because of an unconditional success branch for text replies. After the change, the model must choose an explicit outcome; context is preserved and repeated plain text hits a limit rather than reporting false success. Live rerun after the change ended in clarify. Regression tests cover not_found, clarify, history preservation and the retry limit.

2. Wrong tool choice: an empty keyword result does not mean availability

Repetition 3, q01: the agent searched twice for the Polish word for “classes”. That word is absent from the title “Laboratory — Operating Systems”, so it received zero matches and incorrectly concluded that the day was free. It never called free_busy. A control check of 18:00–20:45 returns is_free=false and evt-018 (17:30–19:00). This is a calendar-access planning error, not a missing document or embedding failure. Possible improvement: require free_busy before availability claims. This extension was not implemented in this change.

3. Generation failure despite available evidence: missing a 15-minute overlap

Repetition 3, q07: the listings and free_busy supplied the correct screening time, 16:00–18:45, and dinner time, 18:30–21:00. The model still said the screening was possible. The intervals overlap by 15 minutes. Evidence acquisition worked here; reasoning while composing the answer failed. Possible improvement: compute interval overlaps in code for every candidate screening.

4. No valid finish call

Repetition 1, q08: the model recognized the missing prices but emitted text resembling finish{…} with template tokens instead of a structured tool call. After 12 turns the code returned step_limit, not success. The other repetitions ended in not_found. This is a model/provider response-protocol limitation; the trace cannot conclusively attribute fault to the provider. Free text is not parsed as a trusted tool call.

5. Retrieval failure: proper names and query wording

q06: the full query about Golem AI and Agentic Workflows does not place the correct chunk in the top-3. A shorter control query (“Golem AI student club hackathon”, translated) finds it in the top-3. This demonstrates ranking sensitivity to wording, not a specific internal model cause. Possible improvement: retry with a shorter phrase or use hybrid search. This case motivates separate retrieval and answer evaluation.

Addendum 2026-11-09: citation hardening

Closed both bypasses found during scope verification: grouped inline citations and citations in clarify/not_found outcomes. Shared finish validation checks all IDs in the list and brackets, including comma- or semicolon-separated IDs. Clarification and abstention may omit citations, but any citations supplied must come from retrieved sources. An invalid finish returns an error observation to the model; repeated errors hit the rejection limit.

17 new regression tests failed before the fix and pass afterward. They cover every finish outcome, standalone finish and finish batched with tools, citation metadata and bounded retries. Regression results and traces. These are deterministic tests using MockClient, the real graph and validator, without new paid LLM calls. Graph topology remains unchanged: 6 working nodes and 16 transitions.

The 30 live runs in this report predate citation hardening (commit a4e0ee4). They were neither rescored nor rerun. Validation at the addendum was 100 tests and Ruff checks. Validation still checks source provenance, not the semantic correctness of each claim.

Manifest SHA-256 hashes use text normalized from CRLF to LF so they match after cloning on another operating system.

Reproduction

Run from the repository root, with the existing environment and an OpenRouter key in local .env. The first embedding-model download needs network access; later runs use the cache. Live evaluation creates a new directory rather than appending to previous traces.

.venv\Scripts\python.exe -m pytest
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m agent_project.eval_rag --output-dir traces/evaluation
.venv\Scripts\python.exe -m agent_project.eval_rag --live --repeats 3 --max-cost-usd 0.25 --output-dir traces/evaluation

Without --live, only local retrieval is measured. To rebuild the index from the same documents:

.venv\Scripts\python.exe -c "from agent_project.rag import DocumentIndex; DocumentIndex.build()"

Recorded validation: 100 passing tests, clean ruff check and ruff format --check. Validation log. Environment versions and file hashes are in the manifest. LLM results vary even at temperature 0. The budget is checked after the provider responds and can be exceeded by one call.
